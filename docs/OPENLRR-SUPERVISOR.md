# OpenLRR AI Lab: supervised Mac test controller (Stage C prototype)

STATUS: CI-tested, NOT YET VALIDATED with the user's Sikarugir/Wine process lifecycle. Do not configure automatic background login/LaunchAgent or leave unattended until the single-run smoke test shows the wrapper and Wine game actually exited.

The controller operates only on the separately installed OpenLRR Menu Test.app. It cannot write code, fetch executable updates on its own, run model-provided shell commands, or modify the user's working game. It requires an explicitly approved DLL SHA256 and a fixed plan.

## Setup

1. Update the checkout: git -C "$HOME/OpenLRR-Agent" pull --ff-only
2. Download a successful reviewed OpenLRR Menu Diagnostics Win32 artifact from GitHub Actions, verify openlrr.dll against SHA256.txt.
3. Copy that approved DLL into "$HOME/Downloads/openlrr.dll".
4. Copy run-autobenchmark.sh, publish-benchmark.sh, and analyze-benchmark.py from "$HOME/OpenLRR-Agent/scripts/macos" into "$HOME/Downloads".
5. Close the TEST app. The normal game must remain untouched.

## Dry-run preflight, then one live smoke test

Use your ACTUAL checked DLL's 64-digit checksum:

    APPROVED_SHA="your-verified-64-digit-lowercase-sha256"

Dry-run; this does NOT start the Mac game:

    python3 "$HOME/OpenLRR-Agent/scripts/macos/lab-supervisor.py" --approved-sha "$APPROVED_SHA" --plan baseline --seconds 60

For an observed smoke test, ensure TEST app is closed, then:

    python3 "$HOME/OpenLRR-Agent/scripts/macos/lab-supervisor.py" --approved-sha "$APPROVED_SHA" --plan baseline --seconds 60 --run

Observe the menu, wait for "Verified test plan finished", and check Activity Monitor for associated Wine/game processes. A receipt only proves the macOS 'open -W' wait helper exited and no open file handles were detected in the dedicated game directory. This is a useful initial gate but not absolute proof that every Wine process is gone. Do not allow multiple unattended repetitions before confirming it works with this Mac wrapper.

After the real-Mac smoke test verifies shutdown, a bounded pair can be run:

    python3 "$HOME/OpenLRR-Agent/scripts/macos/lab-supervisor.py" --approved-sha "$APPROVED_SHA" --plan baseline,gdi --seconds 210 --run

Add --analyze --model gpt-6-luna only when the OpenAI key is present in the terminal. An OpenAI API request runs after both verified uploads. The game-runner subprocess does not inherit OpenAI keys or common GitHub token variables.

## Controls and recovery

STOP:

    touch "$HOME/.config/openlrr-benchmark/STOP"

The Mac runner checks STOP about every two seconds and touches the test-game marker menuperf.stop; the game requests an ordinary WM_CLOSE on its next rendered frame. This is not a hard Wine process kill. If the process is frozen, STOP may require manual closure of only the TEST app and its associated Wine processes.

PAUSE between experiments:

    touch "$HOME/.config/openlrr-benchmark/PAUSE"

Resume:

    rm "$HOME/.config/openlrr-benchmark/PAUSE"

On STOP, timeout, failed upload, or unverifiable exit, the controller fails closed. The safety lock at "$HOME/.config/openlrr-benchmark/supervisor.lock" is deliberately retained after an unsuccessful run, requiring inspection. The benchmark runner may also leave a DLL/markers in place to avoid overwriting the file while the game is still running. The previous DLL backup is preserved under the corresponding "OpenLRR Benchmark Runs/autobenchmark-.../" folder. Do not remove lock, STOP or markers until the TEST process has exited and manual recovery is complete.

Audit records stay at "$HOME/.local/share/openlrr-agent/supervisor-events.jsonl". Benchmark data are uploaded only to MaultzLabs/OpenLRR-Test-Results.

## Boundaries

Fixed plans start with baseline and are limited to four modes; run durations 30..300 seconds. No arbitrary DLL generated by an AI can run on the personal Mac without manual review and SHA pinning. Mac supervisor remains foreground-only pending live smoke validation, reliable wrapper/Wine process identity, disk and resource controls, and a separate isolated execution environment for future AI-generated code. This is not a continuously coding autonomous agent.
