**Status:** Design and partial infrastructure, not an active 24/7 agent. Do not describe it as fully unattended until every safety and lifecycle gate below is tested on the real Mac.

## Desired autonomous loop

1. **Collector** reads latest private sanitized results, build SHAs, local run exit evidence and crash reports. Never import game assets or machine secrets into GitHub.
2. **Analyzer** confirms CSV/schema, matching graphics mode and test DLL, sufficient duration, real presentation success, frame-time outliers, and compares with a repeated baseline.
3. **Coding agent** (Codex SDK / OpenAI Agents SDK, in a restricted development workspace) proposes one narrow hypothesis and changes an experiment-only Git branch. The model does not choose its own security policy or modify test runner, GitHub workflows, credential policies, or allowlists.
4. **GitHub Actions** builds the Win32 x86 DLL and runs deterministic tests. Failed builds are recorded and returned to the coding agent for correction; no Mac execution.
5. **Artifact gate** checks code scope, approved source or previously reviewed patch, the exact commit and executable SHA256, scan results, and CI tests. Automatic execution of newly generated native binaries on the user's personal host is **disabled by default** until a real isolation boundary is deployed and evaluated.
6. **Mac execution worker** runs only explicitly allowed, checksum-pinned builds inside `OpenLRR Menu Test.app`. All runs have a hard wall-clock timeout, verified game exit (not just `WM_CLOSE` post), isolation from the working app, and mandatory restoration of known-good DLL and flags.
7. **Result gate** compares against multiple like-for-like baselines using successful presentation counts, average/p95/max frame presentation time, stability, black-frame or window-state detection, responsiveness and crash data. A "winner" is a candidate for the user's visual acceptance, not an automatically deployed patch.
8. **Notifier** posts candidate details, comparison, PR/commit and artifacts to a private GitHub issue, email, or ChatGPT task notification. An external process must not assume it can inject an unsolicited reply into this exact existing conversation.
9. Repeat until stop condition, fault, human approval, time budget or monetary budget is reached.

## Non-negotiable safety and user controls

- Persistent **PAUSE/STOP switch** checked before every action and before fetching artifacts. Stop cannot silently promote candidate builds; only the user can permit promotion to the working game. Provide a local command and visible status indicator once supervisor is implemented.
- Separate user/worktree/environment for the coding agent; restricted file permissions and short-lived, scoped credentials. GitHub read-only for observer; limited source-branch push for coding; private results write permission for Mac collector only. Never give the coding agent full access to `gh` credentials or all user files.
- The user's Mac / Wine test copy is not a security sandbox for arbitrary AI-generated native code. For genuine unattended arbitrary-code testing, first deploy a separately isolated runner/VM with network and filesystem isolation, and verify the measured graphics performance remains representative of Apple Silicon/Sikarugir. If parity fails, gate actual host execution behind review.
- No shell command generated by the model is sent directly to the Mac controller. The controller exposes a small set of fixed operations and validates schema and paths.
- Set max iterations, max runtime/day, max API spend/day, token/time budgets, disk quota, watchdog, cooling periods, and durable append-only audit trail. Fail closed on unavailable verification, invalid outcomes or process still running.
- No self-update of the supervisor's own safety code.
- The native game `LegoRR.exe`, assets, Wine prefix, and credentials must never be uploaded or committed.
- No modification to the user's normal working wrapper; only a dedicated TEST app with backups.

## Implementation stages

**Stage A — completed:** instrumented Win32 build, local benchmark runner, private uploads, JSON analysis, baseline comparisons and controlled blocking/nowait tests.

**Stage B — next:** explicitly enabled GDI test and trustworthy process-lifecycle detection on the Mac. Add repeatable short fixed-variant runs, crash/visual evidence, and file-based pause/stop. Verify exit before restarting.

**Stage C:** bounded non-AI supervisor for fixed approved test variants. Record state as `idle -> build_verified -> test_running -> results_verified -> scored -> next/paused`. Test STOP, timeout, incomplete GitHub upload, partial results, crash and restart. Permit only preapproved artifacts.

**Stage D:** integrate Codex SDK or Agents SDK; sandbox-generated narrow code changes, CI builds and code review automation, with a strict artifact policy. Autonomous generation is different from unattended execution of generated binaries and needs its own authorization.

**Stage E:** conditional notifications and approval flow. Human approves any changes applied to the working game. Add monitoring as a separate notification mechanism; do not promise that the chat itself is a local daemon.

**Current boundary:** Stage B not yet Mac validated. No background agent or scheduled process has been installed or started on the user's computer by these GitHub commits.
